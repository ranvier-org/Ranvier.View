---
title: RAN016 Reactive read inside an untracked compute phase
order: 16
---

`warning RAN016`: *`scale.Value` runs inside an untracked compute phase, so changes to `scale` never wake this
computation and a pending read fails it.*

**Cause.** Two-phase split primitives (`createMemoOn`, `createEffectOn`, `createAsyncOn`, `createStreamOn`, and
combinators such as `Signal.map`, `Memo.map2`, and `AsyncMemo.bind`) close dependency tracking before the second
phase runs. Inside a reactive computation expression (`memo`, `effect`, `asyncMemo`, `stream`, `editable`, `draft`,
`boundary`, `row`), dependency tracking also closes once `let!` enters its continuation. Any `.Value`, `.TryValue`,
`.Status`, `.Get`, `.TryGet`, or `.Keys` read in that untracked phase records no dependency edge and fails immediately
if the source is `Pending`.

**Fix.** Bind the source with `let!` or `and!` in the tracked phase, or use `.Peek` or `untrack` when an untracked
snapshot is intentional.

### Triggers

```fsharp
module Example

open Ranvier
open Ranvier.CE

let scale = createSignal 2

let scaled (price: Signal<int>) =
    memo {
        let! p = price
        return p * scale.Value
    }
```

### Fixed

```fsharp
module Example

open Ranvier
open Ranvier.CE

let scale = createSignal 2

let scaled (price: Signal<int>) =
    memo {
        let! p = price
        and! s = scale
        return p * s
    }
```
