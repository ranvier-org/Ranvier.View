---
title: RAN018 Reactive read in a computation expression with no let! bindings
order: 18
---

`hint RAN018`: *`count.Value` is read directly inside `memo { ... }` with no `let!` bindings, which skips static source
fusion, `.Graph` resolution, and closed-phase tracking. Bind `count` with `let!`.*

**Cause.** When a `memo`, `editable`, `draft`, `asyncMemo`, `stream`, or `row` computation expression contains zero
reactive `let!` bindings and reads a reactive source (or `item ()` in `row`) directly inside `return`, it compiles in
cold dynamic mode. That skips `.Graph` resolution from the bound source (requiring an active `Graph.Current`), skips
static `map` / `map2` chain fusion, and leaves tracking open across helper calls inside `return`. Zero-bind `effect`
and `boundary` expressions are excluded so dynamic branching patterns stay clean.

**Fix.** Bind the reactive source (or projection `item` in `row`) with `let!`.

### Triggers

```fsharp
module Example

open Ranvier
open Ranvier.CE

let next (count: Signal<int>) =
    memo {
        return count.Value + 1
    }
```

### Fixed

```fsharp
module Example

open Ranvier
open Ranvier.CE

let next (count: Signal<int>) =
    memo {
        let! value = count
        return value + 1
    }
```
