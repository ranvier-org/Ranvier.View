---
title: RAN017 Independent sequential let! in a reactive computation expression
order: 17
---

`hint RAN017`: *`quantity` does not depend on `p`; sequential `let!` forces dynamic tracking and skips static
`map2`/`*On` key cutoff. Write `and!` to bind both sources statically.*

**Cause.** Inside `memo`, `effect`, `asyncMemo`, `stream`, `editable`, `draft`, and `row`, two consecutive `let!`
bindings run sequentially even when the second source expression does not use any value bound by the first. Sequential
`let!` falls back to dynamic tracking (`SourceList`), skips static `Signal.map2` / `Memo.map2` fusion and `*On`
settled-key cutoffs, and short-circuits on the first source when the second is already pending.

**Fix.** Replace the second `let!` with `and!` so the builder merges both sources statically.

### Triggers

```fsharp
module Example

open Ranvier
open Ranvier.CE

let total (price: Signal<int>) (quantity: Signal<int>) =
    memo {
        let! p = price
        let! q = quantity
        return p * q
    }
```

### Fixed

```fsharp
module Example

open Ranvier
open Ranvier.CE

let total (price: Signal<int>) (quantity: Signal<int>) =
    memo {
        let! p = price
        and! q = quantity
        return p * q
    }
```
