# Managed MathML and tree traversal (S13, D01)

Route: managed consumers of two native groups that shipped native-only: S13 MathML (ranvier-org/Ranvier.WebCore#135,
Native23) and D01 NodeIterator/TreeWalker/NodeFilter (ranvier-org/Ranvier.WebCore#137, Native25). Native pin:
Native26 producer `483c0e5`, which carries both groups and the NodeFilterResult generator fix `84dda644`. Managed
versions are I12's: DOM alpha.27, Views 0.1.17, backend alpha.17, native preview.26. No new numbers.

## Core and view state

This work touches the shared DOM contract and the WebCore host adapter, not the view renderer.

- **Core primitives used:** none. Traversal and element identity are DOM state; no reactive graph is involved.
- **View-owned state:** the native handles of NodeIterator and TreeWalker objects (two new release kinds), and one
  `GCHandle` per host NodeFilter holding the managed filter function until the engine releases the filter. Both are
  native-object state with no core equivalent. The pending filter exception of a traversal call is thread-local
  interop state, consumed by the call's status check.

## Contract (Core)

`src/Ranvier.Dom/Generated/Dom.fs` is the native tree's `gen/Ranvier.Dom.fs` at `483c0e5`, byte for byte:
`MathMLMathElement`, `NodeIterator`, `TreeWalker`, `NodeFilter = Node -> NodeFilterResult` with
`NodeFilterResult` Accept = 1, Reject = 2, Skip = 3, `Document.createNodeIterator` and `Document.createTreeWalker`.
The filter getters return `NodeFilter option`. `.github/scripts/dom-contracts.json` pins `483c0e5`.

The browser provider is the erased contract: a Fable function is a DOM filter callback and its enum result is the
FILTER_* number, so no browser adapter is written.

## Native provider (Views)

- `Kind.NodeIterator` = 53 and `Kind.TreeWalker` = 54 release through `rv_dom_node_iterator_release` and
  `rv_dom_tree_walker_release`.
- `Traversal.fs` creates a host filter with `rv_node_filter_create`, drops its own reference after the create call,
  and frees the function's `GCHandle` in the filter's release callback. The filter getters read the function back
  through `rv_node_filter_context`. A filter exception is recorded and the filter reports failure; the engine then
  stops the traversal with `ExistingExceptionError`, and `Interop.check` rethrows the recorded exception with its
  original stack. A result outside NodeFilterResult raises `ArgumentOutOfRangeException` the same way.
- Generator: release kinds for the two roots, hand bodies for the two create methods and the two filter getters,
  hexadecimal IDL defaults (`whatToShow` = `0xFFFFFFFF`), and a `math` row for `MathMLMathElement`, which the
  canonical tag table omits.

## Fixtures

- `TreeTraversal.fs` (shared): iterator and walker defaults, whatToShow masks, Accept/Reject/Skip, filter getter
  identity, filter node identity, a throwing filter (state kept, traversal resumes), live removal and re-entry.
- `MathMLElements.fs` (shared): 13 created and parsed MathML elements, namespace, names, interface, mixin members.
- `TraversalLifecycle.fs` (native): filter released with its walker, with a failed iterator and at host disposal;
  invalid results; wrong thread; disposed walkers; no leaked objects.

## Qualifications

- Chromium 156 has no `MathMLMathElement` interface; `math` is a `MathMLElement` there.
- Re-entering a traversal from its own filter raises InvalidStateError on both engines. Afterwards the engine leaves
  the iterator's `referenceNode` null; reading it crashes Chromium 156's renderer, so the browser run skips the read.
- Unknown HTML elements wrap as `HTMLElement` natively (existing behaviour, outside this group).
