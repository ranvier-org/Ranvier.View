# #144 blob URLs, blob reads and FileReader (Views 0.1.37, native provider)

## Core and view state

- **Core primitives used:** none in the provider. A read is a `ResourceOperation` from the H05 contract, settled by
  `ResourceArbiter` on the host's owner context. A view that reads a blob in a scope starts the read under that scope
  and disposes the operation with `onCleanup`, as `BlobReads` does for H11 reads; disposing a pending read delivers
  `ResourceFailure.Cancelled`. A view that shows an object URL creates it in an effect and revokes it with `onCleanup`
  under the same owner.
- **View-owned state:** `FileReaderObject`, the session's wrapper of the engine's FileReader handle (Kind 98), and the
  provider's table of completion contexts for native reads in flight. Both are native handle state: the core has no
  representation of a native handle, its wrapper identity or a native completion callback.

## Design

- `Ranvier.Dom` `BlobUrlService` (`BlobUrls.fs`): `CreateObjectUrl`, `RevokeObjectUrl`, `ReadUrl` (type and bytes of
  the blob a blob URL refers to), `ReadText` and `ReadBytes` (`Blob.text()`, `arrayBuffer()` and `bytes()`),
  `CreateFileReader`, and `Result` and `Error` for the FileReader members the shared DOM interface leaves out.
  `BrowserBlobUrls.forDocument` calls the realm's `URL`, `fetch`, `Blob.text`, `Blob.bytes` and `FileReader` directly.
- `Ranvier.View.WebCore/BlobUrls.fs`:
  - `BlobUrls.forHost` implements the service for the document the host shows at creation; a call after the host
    shows another document raises `InvalidOperationException`.
  - Object URLs call the generated `rv_dom_domurl_create_object_url` and `rv_dom_domurl_revoke_object_url`; reads call
    `rv_blob_url_read` and `rv_blob_read` and copy the result on completion; FileReader is the generated
    `rv_dom_file_reader_*` family, with `rv_file_reader_result` and `rv_file_reader_error`.
  - `BlobUrls.createFile` makes a file-backed File from an app-supplied absolute path (`rv_file_create_from_path`).

## Proof

`tests/NativeApi.Conformance/BlobUrlChecks.fs` runs 42 shared checks on native JIT, NativeAOT and Chromium: object URL
format, reads of typed, empty, sliced and fragment URLs, revocation, unknown and non-blob URLs, `Blob.text()` and
`bytes()`, owner-bound cancellation, and FileReader event order and final state for every read method, synchronous
abort, abort in `loadstart` and `load`, re-entrant reads and a read inside `loadend`. Progress events are collapsed and
never counted. readAsText without an encoding follows each engine's qualified behaviour (the blob type's charset in
WebKit, UTF-8 in Chromium). The native runner adds the lifetime checks: the wrong thread, a file-backed File read and
then deleted (`NotFoundError`), a relative path, document replacement (a read in flight invalidated, the old URL no
longer loading, the old service rejecting calls), host disposal and no live objects.
