# C01/C02: computed style and pseudo-element queries

The full goal retains all 98 required and five conditional groups. This batch implements C01 and C02 through the engine's live, read-only CSS declaration objects rather than copying a subset of resolved properties.

## Contract and implementation decisions

- Core `Ranvier.Dom.ComputedStyleService.Get(element: Element, pseudoElement: string option): CSSStyleDeclaration` returns the actual engine declaration. `ComputedStyles.forDocument(document)` supplies the browser provider; Views `ComputedStyles.forHost(host)` supplies the native provider. These services borrow the document context. Returned native wrappers are owned by the existing host session and released with it.
- `None`, `Some null` and `Some ""` use the element itself. A pseudo-element string follows getComputedStyle behaviour, including legacy `:before` and valid generated-content pseudo-elements. Invalid/unknown pseudo selectors return an empty declaration, as observed in Chromium and the pinned LocalDOMWindow implementation; this is observable rejection, not a fabricated successful resolved style. The fixture must assert zero length/empty property values. Non-colon strings fall back to the element, matching both implementations.
- Preserve the actual live/read-only declaration semantics: later style changes update reads; attempted writes raise the engine's NoModificationAllowedError. Preserve the difference between an absent pseudo's initial values and an invalid pseudo's empty declaration. Do not compare implementation-specific property counts or the complete serialized declaration across engines.
- The native source authority is `page/DOMWindow+CSSOM.idl` and `LocalDOMWindow::getComputedStyle(Element&, const String&)`, which returns `CSSComputedStyleDeclaration::create`, `createEmpty` or a resolved pseudo element. Reuse that implementation and existing CSSStyleDeclaration transport/wrappers; introduce no computed-style evaluator.
- Extend generation with explicitly selected Window operations bound to a checked Document context. Model this as a context operation, not a fictitious Document member or CSS namespace operation. Check `document.window()` before calling; a windowless document returns unsupported. Feature `dom-computed-style` describes the compiled binding, while each call validates its context.
- Export `rv_dom_window_get_computed_style(document, element, pseudoBytes, pseudoLength, result)`. The result is a retained CSSStyleDeclaration handle. New nullable UTF-8 spans use length -1 for null, zero for empty and positive lengths for complete input; lower lengths, null/nonzero spans and invalid UTF-8 fail without changing output. Existing ABI records/signatures remain unchanged.
- Providers require each element to belong to the service's document. Native providers guard live owning-thread access, reject null/non-native/cross-session element handles, and anchor returned declaration wrappers to the element through the existing session CSSStyleDeclaration cache. Browser providers reject null documents/elements and documents without a Window, then call the document's own Window.
- Core starts a stack after C03 PR258; retain its alpha.10 release and use the next coordinated contract version. Native starts a stack after C03 PR14 without rebasing pushed history. Views records dependencies on the final published batches before pushing its held implementation.
