# D13 form collections, FormData and form events

Route: Qualified (ranvier-org/Ranvier.WebCore#22). Native producer: Native28/ABI36, stacked on G02/G12 (Native27/ABI35)
and I12 (Native26/ABI34). Managed: DOM alpha.29 (Core) and Views 0.1.19 / backend alpha.19.

## Core and view state

This group touches the shared DOM contract and the WebCore host adapter, not the view renderer.

- **Core primitives used:** none. Form collections, FormData entries and submit and formdata events are DOM state;
  the service constructs and reads them and keeps no reactive graph of its own.
- **View-owned state:** none beyond the native object wrappers: DOMFormData handles (release kind `Kind.FormData`),
  the typed SubmitEvent and FormDataEvent wrappers chosen by `Host.event`, and the form collection wrappers. They are
  DOM state of native objects with no core equivalent.

## Contract (Ranvier.Dom)

- Generated interfaces: `HTMLFormElement.submit`/`requestSubmit`, `HTMLFormControlsCollection` (indexed and
  `namedItem -> RadioNodeListOrElement option`), `HTMLOptionsCollection` (length setter, indexed setter, `add`,
  `remove`, `selectedIndex`, `item`, `namedItem`), `DOMFormData` (`append`, `delete`, `has`, `set`), `SubmitEvent`
  and `FormDataEvent`.
- `FormDataService` (hand-written, `FormData.fs`): `Create`, `FromForm (form, submitter)`, `Get`, `GetAll`,
  `Entries`, `CreateSubmitEvent` and `CreateFormDataEvent`. `FormDataEntryValue` is `String` or `File` of an opaque
  `FormDataFile`; `FormDataContract.readFile` raises NotSupportedException until H11 binary value objects.
- Browser provider: `BrowserForms.forDocument` (Fable.Ranvier.Dom). Native provider:
  `Ranvier.View.WebCore.FormData.forHost`.

## Qualifications

- File entries are opaque: a file control contributes a File entry whose name, type and contents are unreadable.
- Host documents never navigate on form submission; the native policy client is not consulted. The shared fixture
  submits into a sink frame so the Chromium page stays in place.

## Verification

- `tests/NativeApi.Conformance/FormChecks.fs` on native JIT, NativeAOT and Chromium: form controls collection order,
  form-attribute association and named lookup; options collection lookup and edits; trusted SubmitEvent and
  FormDataEvent from `requestSubmit` and `submit`, preventDefault, submitter errors (TypeError, NotFoundError);
  FormData construction, entries, mixed File and string values, listener edits; constructed events; disposal.
- Native teardown: thread rejection, a FormData, a collection and a SubmitEvent held past collection, document
  replacement and host disposal, with no live native objects left.
